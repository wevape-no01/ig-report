## 무엇인가

위베이프(인천 구월동)의 인스타그램·스레드 성과를 매일 자동으로 모아 웹페이지로 보여주는 시스템.

- 사이트 https://wevape-no01.github.io/ig-report/
- 저장소 https://github.com/wevape-no01/ig-report
- 갱신 매일 한국시간 오전 7시 자동 (cron `0 22 * * *`, UTC 기준)
- 계정 @wevape.no01(팔로워 721) · @wevape_japan(4) · 스레드 @wevape.no01(1,072)
- 비용 0원, 하루 API 호출 약 69회

## 절대 규칙 — 이것만은 지킬 것

**1. 화면을 고쳤으면 `python3 rebuild.py` 로만 재생성한다.**
`build_*.py` 를 직접 돌리면 컨테이너에 남은 옛 데이터로 페이지가 만들어지고,
그걸 올리면 사이트가 과거로 되돌아가며 "N일째 갱신되지 않았습니다" 빨간 띠가 뜬다.
**2026-08-20과 08-21에 같은 사고가 두 번 났다.** rebuild.py 는 최신 JSON 을 먼저 받고,
페이지를 만들고, 데이터가 36시간보다 오래되면 멈춘다. Meta API 는 호출하지 않는다.

**2. 수집 워크플로를 연달아 돌리지 않는다.**
한 번에 69회 호출이고, 과거에 Meta 개발자 계정이 두 번 차단됐다.
요청 간격 0.4초, 실행당 신규 인사이트 80개 제한이 걸려 있다.

**3. 토큰·비밀번호는 코드·문서·대화에 절대 적지 않는다.**
GitHub Secrets 화면이나 Cloudflare 화면에서 본인이 직접 입력한다.

**4. UI 값은 지시가 있을 때만 바꾼다.**
칸 간격·글꼴 크기·카드 위치는 사용자가 말할 때만 손댄다. 다른 작업을 하면서 곁다리로 조정하지 않는다.
공통 값은 `layout.py` 의 `COMPONENT_CSS` 한 곳에만 둔다. 고친 뒤에는 인스타·스레드 두 페이지의
계산된 값을 재서 전부 같은지 확인한다 (첫 콘텐츠 y 221px · 본문 폭 1265px · 글꼴 1종류).

**5. `history.json` / `threads_history.json` 을 지우지 않는다.**
날짜별 기록이 이 시스템의 유일한 자산이다. 지우면 과거 비교가 전부 사라진다.

## 페이지 구조

```
인스타그램 ─┬ 일일 리포트      index.html
            ├ 주간 리포트      weekly.html  └ 지난 리포트  weekly-past.html
            └ 콘텐츠 분석      analysis.html └ 세부 분석    analysis-detail.html
스레드     ─┬ 일일 리포트      threads.html
            ├ 주간 리포트      threads-weekly.html └ 지난 리포트  threads-weekly-past.html
            └ 콘텐츠 분석      threads-analysis.html └ 세부 분석  threads-detail.html
```

상단 가로줄에서 플랫폼을 고르고, 왼쪽 세로줄에서 페이지를 고른다.
오른쪽 위에 외부 링크 버튼 **발행 관리**(https://znsl132-lang.github.io/wevape-web/)와 알림 종.
폰·태블릿(820px 이하)에서는 상위 메뉴 3개가 첫 줄, 하위 메뉴가 아랫줄에 따로 나온다.

## 파일

| 파일 | 역할 |
|---|---|
| `layout.py` | 공용 껍데기 — 메뉴·색·글꼴·알림. **색/글꼴은 여기 한 곳만 고친다** |
| `rebuild.py` | 최신 데이터 받아 페이지 재생성 (화면 수정 시 이것만 실행) |
| `instagram_api.py` / `threads_api.py` | 데이터 수집 |
| `build_dashboard.py` | 인스타 일일 |
| `build_analysis.py` | 인스타 콘텐츠·세부 분석 |
| `build_threads.py` | 스레드 일일 |
| `build_threads_analysis.py` | 스레드 콘텐츠·세부 분석 |
| `build_weekly.py` / `weekly.py` | 주간·지난 리포트 4개 + 계산 |
| `notice.py` / `fail_issue.py` / `weekly_issue.py` | 알림·이슈 |

데이터 파일: `report_data.json` `history.json` `posts_cache.json`
`threads_report.json` `threads_history.json` `threads_cache.json` `notices.json`

GitHub Secrets: `IG_ACCOUNTS` `THREADS_TOKEN` `GH_PAT` `GITHUB_TOKEN` `ALERT_WEBHOOK`(비어 있음)

## 디자인 규칙

배경 크림 `#F4F1E8` · 메뉴 검정 `#1A1A1A` · 포인트 노랑 `#FFC800` · 카드는 항상 흰색.
글꼴은 `layout.py` 한 곳에서만 정한다(`-apple-system, BlinkMacSystemFont, Segoe UI, Pretendard`).

글자 크기 네 단계: 페이지 제목 24px · 계정/카드 제목 20px · 섹션 제목 18px · 본문 14px · 보조 11~13px.

| 그래프 자리 | 색 |
|---|---|
| 막대 기본 | `#D9D2C2` |
| 막대 강조 (가장 큰 값 하나만) | `#FFCE33` |
| 추이 선 | `#E8C24A` |
| 선 아래 면 | `rgba(255,222,122,.16)` |
| 증감 | 상승 `#1F8A45` · 하락 `#C1392B` |

메뉴·섹션 점·인사이트 띠의 `#FFC800` 은 UI 요소라 그래프보다 진하게 유지한다.

팔로워 수 추이는 가로축 오른쪽 끝에 `(월/일)` `(주 시작일)` `(월)`, 세로축 왼쪽 위에 `(명)`.
세로축 눈금은 딱 떨어지는 숫자로 자동 계산(716·718·720·722).

**위치 통일** — 10개 페이지 모두 첫 카드가 221px에서 시작. 스크롤바 자리를 항상 비워 둬서
페이지를 옮겨도 좌우로 흔들리지 않는다. 이 값을 깨는 수정은 하지 않는다.

## 지표에서 헷갈리기 쉬운 것

- **도달**은 본 사람 수, **조회수**는 표시된 횟수. 조회수가 항상 더 크다.
- **신규 팔로워**는 인스타가 확정해 주는 게 **어제까지**다. 오늘 값은 없다.
- 게시물별 팔로우 수는 **평생 누적**으로만 온다. 그래서 매일 값을 적어 두고(`follows_log`)
  전날과 빼서 그날치를 만든다. 이 계산이 없으면 옛 게시물이 매일 1위가 된다.
- **좋아요 많은 글 ≠ 팔로워 만드는 글.** 실제로 반응률 112위 게시물이 신규 팔로우의 40%를 만들었다.

## 만들 수 없는 것 (API 제약 — 다시 검토하지 말 것)

- **해시태그별 성과** — 어느 태그로 들어왔는지 API가 주지 않는다.
- **경쟁 계정 인사이트** — 계정 주인만 볼 수 있다.
- **스레드 기간별 반응 수** — 계정 단위 일별 반응이 36일치 전부 0으로 온다. 확인된 사실.
  그래서 주간 리포트의 스레드 반응 수치는 주별로 변하지 않는다(조회수만 변한다).
  반응을 보는 유일한 경로가 게시물별 합계 = 누적 반응이고, 세부 분석에 있다.
- 스레드에는 도달 자체가 없고, 게시물별 팔로우 수도 없다.
- 인스타는 프로페셔널 전환 이후 게시물만 인사이트가 있다(240개 중 142개).

## 알림

사이트 종 아이콘 + GitHub 이슈 + 폰 푸시 세 갈래.
푸시는 **담당자 지정**이나 **@멘션**일 때만 확실히 온다(Watch만으로는 안 온다).
팝업은 기기당 알림 하나에 한 번만 뜨고, 7일 지난 알림은 팝업으로 뜨지 않는다.

## 남은 과제

- **사이트 비밀번호** — GitHub Pages로는 불가(Enterprise 전용). Cloudflare Pages로 옮기면 무료로 가능.
  `functions/_middleware.js` 는 이미 저장소에 있다. Cloudflare 가입·환경변수 입력은 본인이 직접.
- **해시태그 수동 점검** — `#전자담배` `#인천전자담배` `#입호흡액상` `#버블몬` `#전담`
  앱에서 눈으로 상위 게시물 경향만 확인.
