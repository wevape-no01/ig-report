# 05 알림 시스템

상위: [[위베이프 SNS 리포트]]

## 세 갈래로 알립니다

| 경로 | 언제 | 어디서 보나 |
|---|---|---|
| 사이트 종 아이콘 | 주간 리포트 발행 / 수집 실패 | 오른쪽 위 종, 팝업 |
| GitHub 이슈 | 주간 리포트 / 수집 실패 | GitHub 저장소 Issues |
| 폰 푸시 | 위 이슈가 생길 때 | GitHub 모바일 앱 |

## 사이트 알림 동작 규칙

- 안 읽은 알림은 **버튼을 누르지 않아도** 팝업으로 바로 뜹니다 (최대 3개)
- 팝업은 **기기당 알림 하나에 한 번만** 뜹니다. 페이지를 옮겨 다녀도 다시 안 뜹니다
- **7일이 지난 알림**은 팝업으로 뜨지 않고 종 목록에만 남습니다
- "읽음" 또는 "열어보기"를 누르면 읽음 처리됩니다
- X는 이번만 숨기기입니다. 안 읽음 상태는 그대로 남습니다
- 폰에서는 팝업이 화면 **아래쪽**에 뜹니다 (위쪽 메뉴를 가리지 않게)

> [!note] 읽음은 기기별로 저장됩니다
> 읽음 표시는 그 브라우저 안에만 저장됩니다(localStorage). PC에서 읽어도 폰은 모릅니다.
> 서버가 없는 구조라 기기 간 동기화는 만들 수 없습니다.

## 폰 푸시가 오게 하려면

GitHub 웹 설정에는 "모바일" 항목이 **없습니다.** 푸시는 앱에서만 켭니다.

또 하나 중요한 점: 저장소를 지켜보기(Watch)만 해서는 새 이슈가 대개 **받은편지함에만** 들어오고
푸시로는 안 옵니다. 확실하게 푸시가 오는 건 두 가지입니다.

1. 이슈의 **담당자로 지정**될 때
2. 댓글에서 **@멘션**될 때

그래서 실패 이슈와 주간 리포트 이슈는 모두 본인을 담당자로 지정해 발행합니다.

## 주간 리포트 이슈

매주 **월요일 오전 7시**(한국시간)에 지난 7일 요약을 이슈로 올립니다.
워크플로 안에서 UTC 일요일인지 확인해 그날만 실행합니다.

## 수집 실패 이슈

제목은 `🔴 데이터 수집 실패`로 시작합니다.
이미 열린 실패 이슈가 있으면 새로 만들지 않고 댓글을 답니다.
다음 실행에서 정상 복구되면 ✅ 댓글을 달고 이슈를 자동으로 닫습니다.

## 테스트용

`test_alert.yml` 워크플로가 남아 있습니다. Actions 탭에서 손으로 실행하면
일부러 실패시켜 알림이 오는지 확인할 수 있습니다. **Meta API를 호출하지 않으므로 안전합니다.**
