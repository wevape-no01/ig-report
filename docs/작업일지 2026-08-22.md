# 2026-08-22 작업

상위: [[위베이프 SNS 리포트]]

## UI 통일 — 공통 CSS 한 곳으로

인스타그램과 스레드 일일 리포트의 칸 간격·글꼴·카드 위치가 조금씩 달랐습니다.
원인은 같은 규칙이 `build_dashboard.py` 와 `build_threads.py` 에 **각각 복사**돼 있어서,
고칠 때마다 한쪽만 바뀌며 슬금슬금 벌어진 것이었습니다.
카드 줄 아래 여백 24px/20px, 설명 캡션 11px/11.5px 같은 식이었습니다.

공통 부품(카드·표·그래프·토글)을 `layout.py` 의 **`COMPONENT_CSS`** 한 곳으로 옮기고,
두 빌더는 그 위에 자기 페이지만의 것(계정 탭, 샘플 배너 등)만 더하도록 바꿨습니다.

마지막 1px은 KPI 카드 아래 보조 줄 때문이었습니다. 인스타는 `.delta`(12px),
스레드는 `.note`(11px)로 클래스 이름이 달라 카드 높이가 어긋났고, 그 아래 카드가 통째로
1px씩 밀렸습니다. 두 클래스를 공통 CSS에서 같은 값으로 묶어 해결했습니다.

## 확인한 방식

두 페이지의 **계산된 스타일 15항목**을 브라우저에서 직접 읽어 비교했습니다.
글꼴, 본문 크기, KPI 행 간격·여백, 카드 padding·radius·배경, 라벨/값 글자 크기,
섹션 padding·margin, 섹션 제목·설명, 기간 버튼, 표 글자·머리·칸, 토글, 섹션 간격.

결과: **15/15 전부 동일.** 10개 페이지 전체로도 첫 콘텐츠 y 221px(차이 0),
본문 폭 1265px, 글꼴 1종류로 확인했습니다.

## 새로 정한 규칙

**UI 값은 지시가 있을 때만 바꾼다.** 다른 작업을 하면서 곁다리로 간격이나 글꼴을
조정하지 않습니다. 공통 값은 `COMPONENT_CSS` 한 곳에만 두고, 고친 뒤에는 두 페이지를
재서 같은지 확인합니다. [[01 사이트 구조]] 맨 앞과 [[00 인수인계]] 절대 규칙 4번에 넣었습니다.

## 함께 한 것

업계 평균 비교 계산식을 바로잡았습니다. Socialinsider는 (좋아요+댓글)÷팔로워인데
우리는 저장·공유까지 더하고 있어서 "업계 평균의 1.9배"가 부풀려져 있었습니다.
같은 식으로 다시 재니 1.7배입니다. 자세한 건 [[03 지표 정의]]와 [[06 문제 해결 기록]].

인사이트 상자 아래에 근거 한 줄(기간·게시물 수·계산식)을 넣었습니다.

경쟁·카테고리 계정 조사 기능은 검토했지만 **하지 않기로** 했습니다.
자동 수집은 API가 막혀 있고, 브라우저로 긁는 건 계정 정지 위험이 있으며,
수동 기록은 매일 사람 손이 듭니다. [[04 알 수 없는 것들]] 참고.

## 추가 (같은 날, 뒤늦게)

사용자가 "반응률에 대한 건 페이지에 안 뜬다"고 지적했습니다. 확인해 보니
업계 평균 비교와 근거 표기가 **콘텐츠 분석(analysis.html)에만** 들어가 있었고,
사용자가 보던 **주간 리포트(weekly.html)에는 반응률 숫자만** 있었습니다.
처음 요청에서 "주간 리포트의 반응률"이라고 했는데 콘텐츠 분석만 고친 것이 원인입니다.

인스타 주간 리포트에 반응률 바로 아래 근거 칸을 넣었습니다 (스레드는 제외하기로 함).
- 계산식: (좋아요+댓글+저장+공유) ÷ 도달 × 100
- 업계 비교: (좋아요+댓글) ÷ 팔로워 × 100 = 0.83% → 업계 평균 0.48%의 1.7배
- 출처와 한계 한 줄

**주의할 점** — 처음엔 주간 리포트가 `report_data.json` 의 게시물(12개)만 써서
같은 지표인데 1.5배로 나왔습니다. 콘텐츠 분석은 `posts_cache.json` 최근 24개월
(115개) 기준이라 1.7배입니다. 같은 지표가 페이지마다 다르면 안 되므로
`weekly._rate_ig_basic()` 이 콘텐츠 분석과 **같은 글 묶음**을 읽도록 맞췄습니다.
`weekly.BENCH_MONTHS` 와 `build_analysis.ANALYSIS_MONTHS` 는 항상 같아야 합니다.

UI는 건드리지 않았습니다. 10개 페이지 첫 콘텐츠 위치·본문 폭·글꼴 수 모두 동일 확인.

## 추가 2 — 반응률 통일과 근거 기반 진단

### 반응률을 하나로

사용자 지적: "업계 산출 방식으로 고쳤으면 '그대로 볼 수 없다'는 말은 뺄 수 있잖아."
맞는 말이었습니다. 대표 반응률 자체를 업계와 같은 식으로 바꾸고 그 설명을 지웠습니다.

- 대표 반응률 = **(좋아요+댓글) ÷ 팔로워 × 100** = 0.83% = 업계 평균 0.48%의 1.7배
- 도달 대비 반응(3.1%)은 없애지 않고 "소재의 힘"을 보는 보조 지표로 옆에 둡니다.
  성격이 다른 값이라 업계 평균과는 비교하지 않습니다.
- 주간 리포트와 콘텐츠 분석 두 곳 모두 같은 값을 씁니다.

**팔로워 100명 미만이면 업계 비교를 내지 않습니다.** 위베이프 재팬(팔로워 4명)에서
"업계 평균의 109.4배"가 나왔습니다. 분모가 작으면 비율이 터집니다.
`weekly.BENCH_MIN_FOLLOWERS` / `build_analysis.MIN_FOLLOWERS_FOR_BENCH` = 100.

### advice.py 신설 — 근거 있는 진단만 만든다

인사이트를 **근거 / 해석 / 실행** 세 줄로 나눴습니다. 숫자와 판단이 섞이지 않게 하려는 것입니다.
계산과 판정은 `advice.py` 에서만 하고, 문장 조립은 `build_analysis.py` 에서 한 번만 합니다.

원칙 네 가지 — 표본 수 없는 주장은 만들지 않는다 / 기간이 다른 두 묶음을 비교하지 않는다 /
API 가 값을 안 주는 것과 0 인 것을 구분한다 / 확실하지 않으면 확실하지 않다고 쓴다.

### 데이터에서 실제로 나온 것

1. **발행이 멈춘 것이 가장 큰 문제.** 2025-11 23개(신규 팔로우 35건) → 최근 3개월 월 2.3개
   (신규 팔로우 합계 1건). 도달 중앙값도 203명 → 116명.
2. **릴스가 피드보다 도달 2.5배** (같은 기간 안에서 릴스 10개 vs 피드 69개, 중앙값 378 대 152).
   공유 0.80 대 0.19건.
3. **해시태그는 효과 없음.** 전체 기간으로 재면 있는 쪽이 좋아 보이는데 시기 효과였습니다.
   같은 기간(2025-12-29 이후)만 보면 0.78% 대 0.81% 로 차이가 없습니다.
4. **신규 팔로워의 62%를 상위 21개 글이 만듦.** 성과가 소수에 쏠려 있습니다.
5. **도달 100명당 팔로우 0.27건.** 캡션에 프로필로 넘어올 이유가 없습니다.

> [!warning] 릴스는 팔로우 수를 알 수 없다
> 인스타그램 API 는 릴스에 `follows` 와 `profile_visits` 를 **아예 주지 않습니다** (None).
> 이걸 `or 0` 으로 읽으면 "릴스는 팔로워를 못 데려온다"는 **틀린 결론**이 나옵니다.
> `posts["follows_known"]` 로 구분해 두었습니다. 릴스 효과는 주 단위 계정 전체
> 팔로워 증감으로 판단해야 합니다.

## 추가 4 — 지난 분석 다듬기

**x축 기준이 없던 문제.** `drawLine(svg, pts, dec, unit, yUnit)` 을 부르면서 x축과 y축에
같은 값을 넘기고 있었습니다. 그래서 세로축 단위 `(%)` 가 가로축 자리에도 찍혔습니다.
인자 이름을 `xUnit` 으로 바꾸고 `(기준 주 · 월/일)` 을 넘깁니다.
그래프 아래에 "가로축은 각 주의 월요일입니다 · 기간 · 점 개수" 한 줄도 붙였습니다.

**주간 기록이 너무 길던 문제.** 41줄이 한 번에 나와 스크롤이 길었습니다.
최신순 10줄씩 끊고 아래에 `‹ 1 2 3 4 5 ›` 와 그 쪽의 기간을 답니다.
쪽 번호는 표(tbody)만 다시 그립니다 — 페이지 이동이 아니라서 스크롤이 튀지 않습니다.

> [!tip] 쪽을 넘길 때 화면이 움직이지 않게 하는 법
> 마지막 쪽은 줄 수가 적어 표가 짧아지고, 그러면 아래 쪽 번호가 위로 올라옵니다.
> `.tbl-box { min-height:356px }` 로 10줄 높이를 고정했습니다.
> 처음엔 352px 로 뒀는데 10줄일 때 355~356px 이라 4px 흔들렸습니다.
> 브라우저에서 재서 356 으로 맞췄습니다.

검증: 1~5쪽을 차례로 눌러 표 높이 356px 고정, 쪽 번호 위치 1471px 고정, 스크롤 0 유지 확인.
지표를 바꿔도 세로축은 (%) / (개) / (건) 로 바뀌고 가로축은 (기준 주 · 월/일) 로 유지됩니다.
