# 02 자동 갱신 구조

상위: [[위베이프 SNS 리포트]]

## 매일 아침 벌어지는 일

GitHub Actions가 **매일 한국시간 오전 7시**(cron `0 22 * * *`, UTC 22시)에 깨어나서
아래 순서로 일합니다. GitHub 사정으로 몇십 분 늦을 수 있습니다.

1. 저장소를 내려받고 파이썬을 준비한다
2. 인스타그램 데이터를 받아온다 → `report_data.json`, `history.json`, `posts_cache.json`
3. 스레드 데이터를 받아온다 → `threads_report.json`, `threads_history.json`, `threads_cache.json`
4. 받은 데이터로 HTML 10개를 다시 만든다
5. 월요일이면 주간 리포트를 GitHub 이슈로 발행한다
6. 바뀐 파일을 저장소에 커밋한다 (`리포트 자동 갱신 2026-08-20` 같은 메시지)
7. GitHub Pages가 커밋을 감지해 사이트를 새로 배포한다

배포까지 합해 보통 2~3분이면 끝납니다.

## Meta가 계정을 막지 않게 하는 장치

과거에 짧은 시간에 요청을 몰아 보내서 **개발자 계정이 두 번 차단된 적**이 있습니다.
그래서 지금은 다음 제한을 걸어 두었습니다.

| 장치 | 값 | 이유 |
|---|---|---|
| 요청 사이 최소 간격 | 0.4초 | 몰아치기 방지 |
| 한 번에 새로 받는 게시물 인사이트 | 최대 80개 | 첫 실행 폭주 방지 |
| 다시 받아오는 게시물 범위 | 최근 30일 | 오래된 글은 값이 안 변함 |

정상 상태의 하루 호출량은 **인스타 43회 + 스레드 26회 = 약 69회**입니다.

> [!warning] 지켜야 할 규칙
> 코드를 고쳤다고 워크플로를 여러 번 돌리면 안 됩니다. 한 번 돌릴 때마다 69회씩 호출됩니다.
> 화면만 고칠 때는 데이터를 새로 받지 말고, 이미 저장소에 있는 JSON으로 HTML만 다시 만드세요.
> 이 방법은 API 호출이 **0회**입니다.
>
> 이때 `python3 rebuild.py` 를 쓰면 최신 데이터를 먼저 받아오고 검사까지 해 줍니다.
> `build_*.py` 를 직접 돌리면 옛 데이터로 만들어질 수 있습니다. [[06 문제 해결 기록]] 참고.

## 저장되는 파일

| 파일 | 담는 것 |
|---|---|
| `report_data.json` | 인스타 프로필·최근 게시물·계정 인사이트 |
| `history.json` | 인스타 날짜별 기록 (팔로워·도달·조회수) |
| `posts_cache.json` | 인스타 전체 게시물 + 인사이트 |
| `threads_report.json` | 스레드 프로필·최근 글 |
| `threads_history.json` | 스레드 날짜별 기록 |
| `threads_cache.json` | 스레드 전체 글 + 인사이트 |
| `notices.json` | 사이트 알림 목록 |

날짜별 기록이 이 시스템의 핵심 자산입니다. **이 파일들이 지워지면 과거 비교가 전부 사라집니다.**

## 저장해 둔 비밀값 (GitHub Secrets)

| 이름 | 용도 |
|---|---|
| `IG_ACCOUNTS` | 인스타 계정 + 토큰 |
| `THREADS_TOKEN` | 스레드 토큰 (60일 만료, 7일마다 자동 갱신) |
| `GH_PAT` | 토큰 갱신 시 시크릿을 다시 쓰기 위한 권한 |
| `GITHUB_TOKEN` | 이슈 발행 (GitHub이 자동 제공) |
| `ALERT_WEBHOOK` | 슬랙·디스코드 알림 (지금은 비어 있음) |

토큰 값은 코드나 문서에 절대 적지 않습니다. GitHub 설정 화면에서만 넣습니다.

## 실패하면

수집이 실패하면 자동으로 GitHub 이슈 **🔴 데이터 수집 실패**가 만들어지고
본인에게 담당자로 지정됩니다. 폰에 GitHub 앱이 있으면 푸시로 옵니다.
사이트 종 아이콘에도 알림이 뜹니다. 다음 실행에서 복구되면 이슈가 자동으로 닫힙니다.

자세한 건 [[05 알림 시스템]].
